# Changelog

## [0.1.9] — 2026-09-24

### Изменено
- `.save(...)` у `Result`, `SelectionPipeline`, `ModelReport` внутри активного
  `Experiment(clearml=True)` теперь **дублирует результат в ClearML** (таблицы и графики) и печатает
  об этом строку. Раньше эти методы писали только файлы на диск, и графики в Plots не попадали.
  Управление: `to_clearml=None` (авто), `True`, `False`. Вне эксперимента поведение прежнее.
- `Experiment.current()` — активный эксперимент с ClearML.

## [0.1.8] — 2026-09-24

Версия 0.1.7 вышла без обновлённых примера и README; в 0.1.8 они исправлены.



### Добавлено
- `Experiment.save_report(report)`, `Experiment.save_pipeline(pipe)`, `Experiment.log(obj)`:
  отчёт по модели и пайплайн отбора отправляются в ClearML (таблицы и графики) и сохраняются
  локально. Раньше для них были только `report.save()` / `pipe.save()`, которые пишут файлы на
  диск и в ClearML ничего не отправляют, — в примере это вводило в заблуждение.

### Исправлено
- Пример `examples/` и README: результаты отправляются через `exp.save_pipeline/save_report`.

## [0.1.6] — 2026-09-24

### Добавлено
- `Experiment.close()` всегда печатает итог по графикам одной строкой: сколько отправлено, сколько
  подтверждено сервером, какие не отправлены и почему (раньше молчал и при успехе, и при сбое).
- `Experiment.plots_summary()` / `tracking.clearml.plots_summary()`: таблица по каждому графику —
  отправлен ли, причина отказа, подтверждён ли сервером.
- Ошибка `report_plotly` больше не теряется: причина в журнале и предупреждение.
- Если активной задачи ClearML нет (например, `Experiment` без `clearml=True`), `close()` сообщает,
  что графики не отправлены.

## [0.1.5] — 2026-09-24

### Исправлено
- `tracking.clearml.diagnose()` давал ложный результат «график не дошёл» на сервере, где графики
  сохранялись: доставка проверялась чтением самих графиков (`get_reported_plots`), а сервер отдаёт
  их страницами, ограниченными по размеру, и крупные в ответ не попадают. Теперь используется
  список метрик с событиями `plot` (не зависит от размера). То же для сверки в `Experiment.close()`;
  если сервер такую проверку не поддерживает — предупреждений нет (лучше промолчать).
- `diagnose()` больше не пишет тестовые графики в вашу рабочую задачу: работает во временной
  задаче, которая удаляется (`keep=True` — оставить). Намеренные ошибки пробы не попадают в
  предупреждения активного `Experiment`.

## [0.1.4] — 2026-09-24

### Исправлено
- Графики не попадали в ClearML Plots, если фигура превышала лимит запроса сервера: ClearML
  отбрасывает такой запрос без исключения (только строка `ERROR` в логе). `plot_distribution` и
  гистограммы `eda_transactions` вшивали в фигуру все значения (десятки МБ на миллионе строк) —
  теперь используются предподсчитанные бины (размер фигуры не зависит от числа строк).
- `Experiment.save_result` молча глотал ошибку построения графика — теперь предупреждение.

### Добавлено
- `tracking.clearml.report_figure` проверяет размер и прореживает слишком большие фигуры;
  `ErrorWatch`, `verify_plots`, `diagnose()` (поиск лимита сервера), `Experiment.close()` сообщает
  о недошедших графиках и ошибках ClearML; `plotting.histogram/shrink_figure/figure_size_mb`;
  лимит настраивается `COLLECTION_LAB_CLEARML_MAX_MB`.

## [0.1.3] — 2026-09-24

### Добавлено
- `incremental_feature_eval(eval_sets={...})`: метрика на любом числе внешних наборов (val, test,
  другие) на каждом шаге; график показывает train (CV), val, test на одной картине, изменение
  на шаге по наборам и долю полезного сигнала. Наборы ни на что не влияют: признаки выбираются
  только по CV на train, число деревьев берётся из CV.
- `DataSplit.eval_sets(parts=("val", "test"))`, `core.iterations_param`.

## [0.1.2] — 2026-09-24

### Исправлено
- CSV-файлы (`selection_log.csv`, `*_table.csv`, отчёт по модели, `Experiment.save_table`)
  записывались в UTF-8 без BOM, и Excel показывал кириллицу кракозябрами. Теперь `utf-8-sig`;
  pandas читает такие файлы как обычно.

## [0.1.1] — 2026-09-24

### Исправлено
- `Experiment(clearml=True)` падал при повторном запуске в одном ядре (`UsageError: Current task
  already created and requested task name 'v_2' does not match ... 'v_1'`): предыдущая задача
  ClearML теперь закрывается автоматически.
- Ошибка создания задачи ClearML оставляла пустую папку версии и «сжигала» номер.
- Явная `version=N` при существующей папке молча перезаписывала файлы — теперь `FileExistsError`
  (или `overwrite=True`).
- В git не попадал пакет `collection_lab.data` (правило `.gitignore` `data/`).

### Добавлено
- `Experiment` как контекстный менеджер, идемпотентный `close()`, `Experiment.list_versions`.

## [0.1.0] — 2026-09-23

Первая версия: перенос наработок из `ML_lib/scr` и ноутбуков RTK в устанавливаемый пакет.

### Добавлено
- `data`: определение и приведение типов, `time_split` / `random_split`, `DataSplit`
  с проверкой непересечения частей.
- `core`: адаптеры LightGBM / CatBoost с единым интерфейсом, `FeaturePreparer`
  (категории фиксируются по train), `cross_validate` с сегментами и OOF, `Result`.
- `metrics`: AUC / Gini / KS / logloss, метрики по сегментам, PSI / CSI / PSI по периодам,
  `gain_chart` (интерфейс `risk_instruments`), калибровка, Хосмер–Лемешоу, WoE / IV.
- `selection`: `quality_filter`, `correlation_filter`, `univariate_scores`, важности
  (кумулятивная, permutation, drop-column), единый `rfe`, backward / forward / incremental,
  `SelectionPipeline`.
- `eda`: обзор таблицы, распределения, динамика таргета, винтажи и EDA транзакций.
- `modeling`: `train_model`, `compare_models`, `tune_hyperparams` (Optuna, выбор по val),
  `sample_size_curve`.
- `validation`: `plot_stab` (интерфейс `risk_instruments`), динамика метрик,
  `model_report` с HTML-выгрузкой.
- `tracking`: `Experiment` (версии `v_N`, модель, признаки, метрики, графики) + ClearML.
- Все графики — plotly; параметры по умолчанию — в `config.py`.
