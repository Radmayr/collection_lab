# Changelog

## [0.2.0] — 2026-10-03

### Добавлено
- Новый раздел `feature_testing` — что даст модели добавление новых признаков:
  - `test_features(split, base, candidates)` — каждый кандидат отдельно и все вместе: прирост
    метрик по кросс-валидации на train с доверительным интервалом, прирост на val и test
    (бутстрап), покрытие, корреляция с базой, PSI, вердикт `better` / `same` / `worse`;
  - `test_domains(split, base, domains)` — домен данных целиком: прирост, покрытие, прирост на
    покрытой части, качество домена в одиночку, вклад признаков внутри домена;
  - `base` — список признаков, модель (адаптер, `.pkl` эксперимента, папка экспорта, нативный
    LightGBM / CatBoost) или имя колонки со скором; `how="retrain"` — переобучить с
    кандидатами, `how="on_top"` — дообучить поверх скора только на кандидатах;
  - `segment="колонка"` — прирост по сегментам; при большом числе кандидатов — быстрый отсев
    перед точной оценкой (`max_exact`);
  - `FeatureTest`: `summary`, `metrics`, `segments`, `features`, `plot()`, `plot_segments()`,
    `plot_metrics()`, `plot_domain()`, `replacement()` (добавить или заменить похожий признак
    базы), `save()`; `exp.log(test)` / `exp.save_feature_test(test)`.
- `metrics`: `pr_auc`, `brier`, `lift` и имена `"pr_auc"`, `"brier"`, `"lift@10%"` (процент
  любой) в `get_metric`.
- `examples/04_feature_testing.ipynb` — пример по всему разделу.

## [0.1.12] — 2026-09-28

### Добавлено
- `eda.vintage(df, sample, ...)`: объединяет `maturation_transactions` + `plot_vintage` в один
  вызов для одной выборки — по аналогии с `vintage_by_type` для нескольких. Сами
  `maturation_transactions`/`plot_vintage` остаются доступны отдельно.
- `eda.vintage_by_segment(df, segment_col, ...)`: винтажи разных популяций (продуктов, каналов)
  на одном графике — **у каждого сегмента своя база**; `segments` / `top_k` / `min_contracts`,
  `population` делится по сегменту. Для типов транзакций внутри одной популяции — по-прежнему
  `vintage_by_type` (общая база).
- `examples/eda_overview.ipynb` (+ `build_eda_notebook.py`): прогон всех функций `eda` на
  `df_1.csv`, каждый вызов — со всеми параметрами явно и комментарием, что в них передаётся.

### Исправлено
- `vintage_by_type` считал базу (число договоров и суммарный баланс) отдельно для каждого типа —
  только по договорам с транзакциями этого типа, а договоры без транзакций выделял в тип `NA`.
  Доли по типам не складывались в общий винтаж (на `df_1`/PHX: −34,4 % вместо 3,80 %). Теперь база
  одна для всех типов (все договоры выборки или `population`), по типу делятся только транзакции:
  `cum_share_of_balance`, `cum_tx_sum`, `cum_tx_cnt` по типам в сумме равны общему винтажу.
- `vintage_by_type`: горизонт урезался по последней ретро-дате внутри каждого типа — у типов мог
  получиться разный горизонт. Теперь один общий.
- Тесты зависели от сети: проверка доставки графиков открывала настоящую сессию ClearML даже с
  поддельной задачей, и при выключенном сервере набор тестов шёл 25+ минут вместо минуты. Сетевой
  запрос вынесен в `_request_plot_metrics`, в тестах он по умолчанию запрещён.

### Изменено
- Заголовки и подписи оси Y у `plot_vintage`/`vintage`/`vintage_by_type` — на русском
  («накопленная доля от баланса», «конверсия в транзакцию» и т.д. — `eda.vintage.Y_LABELS`)
  вместо сырых имён колонок (`cum_share_of_balance`).

## [0.1.10] — 2026-09-24

## [0.1.5] — 2026-09-24

### Исправлено
- `tracking.clearml.diagnose()` давал ложный результат «график не дошёл» на сервере, где графики
  сохранялись: доставка проверялась чтением самих графиков (`get_reported_plots`), а сервер отдаёт
  их страницами, ограниченными по размеру, и крупные в ответ не попадают. Теперь используется
  список метрик с событиями `plot` (не зависит от размера). То же для сверки в `Experiment.close()`;
  если сервер такую проверку не поддерживает — предупреждений нет (лучше промолчать).
- `diagnose()` больше не пишет тестовые графики в вашу рабочую задачу: работает во временной
  задаче, которая удаляется (`keep=True` — оставить). Намеренные ошибки пробы не попадают в
  предупреждения активного `Experiment`.

## [0.1.0] — 2026-09-23

Первая версия: перенос наработок из `ML_lib/scr` и ноутбуков RTK в устанавливаемый пакет.

### Добавлено
- `data`: определение и приведение типов, `time_split` / `random_split`, `DataSplit`
  с проверкой непересечения частей.
- `core`: адаптеры LightGBM / CatBoost с единым интерфейсом, `FeaturePreparer`
  (категории фиксируются по train), `cross_validate` с сегментами и OOF, `Result`.
- `metrics`: AUC / Gini / KS / logloss, метрики по сегментам, PSI / CSI / PSI по периодам,
  `gain_chart` (интерфейс `risk_instruments`), калибровка, Хосмер–Лемешоу, WoE / IV.
- `selection`: `quality_filter`, `correlation_filter`, `univariate_scores`, важности
  (кумулятивная, permutation, drop-column), единый `rfe`, backward / forward / incremental,
  `SelectionPipeline`.
- `eda`: обзор таблицы, распределения, динамика таргета, винтажи и EDA транзакций.
- `modeling`: `train_model`, `compare_models`, `tune_hyperparams` (Optuna, выбор по val),
  `sample_size_curve`.
- `validation`: `plot_stab` (интерфейс `risk_instruments`), динамика метрик,
  `model_report` с HTML-выгрузкой.
- `tracking`: `Experiment` (версии `v_N`, модель, признаки, метрики, графики) + ClearML.
- Все графики — plotly; параметры по умолчанию — в `config.py`.

### Исправлено относительно `scr`
- См. раздел «Что исправлено» в README.
