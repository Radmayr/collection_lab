# Примеры

Все ноутбуки работают на встроенных демо-данных и запускаются сразу после установки библиотеки.
В каждом есть ячейка **«Настройки»** — единственная, которую нужно поменять, чтобы запустить
ноутбук на своей таблице: откуда читать данные и как называются колонки. Всё, что ниже неё, от
конкретных колонок не зависит.

Ноутбуки лежат в репозитории **без результатов**; чтобы увидеть таблицы и графики, выполните
ноутбук.

| № | Ноутбук | На какой вопрос отвечает | Таблица на входе |
|---|---|---|---|
| 1 | [01_eda_overview.ipynb](01_eda_overview.ipynb) | Что лежит в таблице и как пользоваться каждой функцией `eda` | транзакции по договорам |
| 2 | [02_vintage_overview.ipynb](02_vintage_overview.ipynb) | Сколько и когда поступает после контрольной даты — по сегментам, типам транзакций, когортам | транзакции по договорам |
| 3 | [03_model_pipeline.ipynb](03_model_pipeline.ipynb) | Как построить модель от данных до отчёта и сохранённого эксперимента (LightGBM) | признаки и таргет |
| 4 | [04_feature_testing.ipynb](04_feature_testing.ipynb) | Что даст модели добавление новых признаков и доменов данных | признаки и таргет |
| 5 | [05_catboost_pipeline.ipynb](05_catboost_pipeline.ipynb) | Как построить модель, если финальная модель — CatBoost | признаки и таргет |

## Какие таблицы нужны

**Транзакции по договорам** (ноутбуки 1–2; демо — `cl.data.make_demo_transactions()`): одна
строка — либо одна транзакция, либо договор без транзакций (поля транзакции пустые). Колонки
договора повторяются в каждой его строке.

| Что | Настройка |
|---|---|
| идентификатор договора | `CONTRACT` |
| контрольная дата договора — от неё считаются дни до транзакции | `START_DATE` |
| баланс на контрольную дату | `BALANCE` |
| разрез договоров: продукт, канал | `SEGMENT` |
| дата, сумма и тип транзакции | `TX_DATE`, `TX_AMOUNT`, `TX_TYPE` / `TX_TYPES` |
| дата актуальности выгрузки | `PROCESSED_DT` |

**Признаки и таргет** (ноутбуки 3–5; демо — `cl.data.make_demo_data()`): одна строка — одно
наблюдение.

| Что | Настройка |
|---|---|
| бинарный таргет 0 / 1 | `TARGET` |
| дата наблюдения и граница отложенной выборки | `DATE`, `OOT_FROM` |
| колонка сегмента (необязательно) | `SEGMENT` |
| признаки | `FEATURES` / `NOT_FEATURES`, в ноутбуке 4 — `DOMAINS` |

## Что считает каждый ноутбук

### 1. `01_eda_overview` — справочник по модулю `eda`

Каждая функция вызвана один раз, все параметры прописаны явно с комментарием.

- `overview`, `target_summary` — типы, пропуски, уникальные значения; размер выборки и доля флага
  целиком и по сегментам;
- `plot_distribution`, `plot_target_rate_by_bins` — распределения баланса и суммы транзакции,
  доля флага по бинам баланса;
- `wilson_ci`, `target_dynamics` — доля флага по кварталам с доверительным интервалом;
- `vintage`, `vintage_by_type`, `vintage_by_segment` — винтажи (кратко; подробно — в ноутбуке 2);
- `eda_transactions` — сводный отчёт по транзакциям: обзор, пропуски, квантили, агрегаты по
  договору, топ договоров, графики.

### 2. `02_vintage_overview` — винтажи

Винтаж — накопленные поступления по дням от контрольной даты: **доля от баланса** (сколько
поступило) и **конверсия в транзакцию** (у какой доли договоров была хотя бы одна транзакция).

- общий винтаж основного сегмента и значения на ключевых сроках;
- разрезы по типам транзакций — с общей базой, сумма по типам равна общему винтажу;
- только крупные транзакции — как фильтровать суммы и не потерять базу (`population`);
- все сегменты на одном графике; то же для крупных транзакций;
- когорты по кварталам контрольной даты — виден дрейф;
- типы транзакций внутри каждого сегмента;
- произвольный набор кривых на одном графике (`maturation_transactions` + `plot_vintage`).

### 3. `03_model_pipeline` — модель от данных до эксперимента (LightGBM)

1. типы признаков;
2. сплит без утечек: test — отложенный по времени, отбор и подбор параметров только на train/val;
3. EDA: динамика таргета, распределения;
4. отбор признаков одним пайплайном (качество → корреляции → важность → RFE) с общим логом
   «почему выбыл признак»;
5. обучение и подбор параметров (Optuna, выбор по val);
6. отчёт: метрики, калибровка, gain chart, сегменты, стабильность признаков, PSI — общий и по
   месяцам test относительно train;
7. сохранение эксперимента (локально и в ClearML).

[model_pipeline.py](model_pipeline.py) — тот же путь скриптом, без графиков:

```bash
python examples/model_pipeline.py                      # на демо-данных
python examples/model_pipeline.py data.csv --target target --date report_date \
    --oot-from 2024-03-01 --drop client_id            # на своей таблице
```

### 4. `04_feature_testing` — новые признаки и домены

Есть разработанная модель и новые данные; нужно понять, что они дадут. В настройках задаются
домены (группы признаков по источнику), какие из них уже в модели, а какие новые.

1. несколько новых признаков: каждый отдельно и все вместе, сводка и графики;
2. прирост по сегментам;
3. база — готовая модель (объект, файл эксперимента, папка экспорта, нативная модель);
4. база — только скор готовой модели (`on_top`);
5. десятки кандидатов: быстрый отсев и точная оценка лучших;
6. добавить или заменить похожий признак базы;
7. домены целиком: прирост, покрытие, вклад признаков внутри домена;
8. свои метрики, точность интервалов, сохранение в эксперимент.

### 5. `05_catboost_pipeline` — финальная модель CatBoost

Тот же путь, что в ноутбуке 3, но итоговая модель — CatBoost: алгоритм выбирается аргументом
`model="catboost"`.

1. типы признаков и сплит без утечек;
2. отбор признаков (шаг важности — на CatBoost);
3. LightGBM против CatBoost на одних и тех же фолдах;
4. подбор параметров CatBoost (Optuna, выбор по val);
5. финальная модель на train + val с найденным числом деревьев;
6. отчёт: метрики, калибровка, важности, сегменты, PSI по месяцам;
7. чем CatBoost отличается от LightGBM в библиотеке;
8. выгрузка для инференса без библиотеки (`model.cbm` + `inference.py`);
9. сохранение эксперимента.

## Как запустить

```bash
pip install "collection_lab[all] @ git+https://github.com/Radmayr/collection_lab.git"
```

Выполнить целиком из командной строки и сохранить результат рядом (файлы `*_executed.ipynb` в git
не попадают):

```bash
jupyter nbconvert --to notebook --execute examples/04_feature_testing.ipynb \
    --output 04_feature_testing_executed.ipynb
```

## Как менять

Ноутбуки собираются скриптами из [builders/](builders/) — правьте скрипт и пересобирайте, а не
сам `.ipynb`:

```bash
python examples/builders/build_feature_testing.py
```
